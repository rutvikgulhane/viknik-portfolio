# Viknik Portfolio Release Discipline

- A push to `main` triggers a paid Netlify deployment (about 15 credits). Treat it as a release, not a save action.
- Make and validate related changes locally first. Batch small refinements into one reviewed release whenever practical.
- Never push to `main` unless Rutvik explicitly asks to commit and push the reviewed batch. Do not ask proactively whether to push.
- For responsive layout work or a reported visual regression, verify the production build and check the affected desktop and mobile/tablet layouts before offering a release.
- Preserve unrelated local changes and report exactly what is ready for the next release.
